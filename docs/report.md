# AI Scientist 评分机制原理与优势解析报告

> 目标：总结本轮开发中对评分机制的完整设计，包括各评分体系的计算原理、维度构成、与迭代闭环的联动，以及每项机制的核心优势。
> 更新日期：2026-08-17

---

## 一、评分体系总览

本项目包含 **两类评分指标** 和 **一套迭代闭环机制**，共同构成质量评估与优化体系：

| 层级 | 指标 | 判定方 | 评分范围 | 回答的问题 |
|---|---|---|---|---|
| 假设质量 | **综合得分（overall_score）** | Critic Agent（LLM 评审） | 0–10 | 这个假设好不好？ |
| 计划细节 | **颗粒度得分（granularity_score）** | 算法计算 | 1–6 | 这个假设够不够具体可操作？ |
| 迭代优化 | **跨轮次评分闭环** | Orchestrator + Critic + Scientist | 与前几轮对比 | 假设有没有越改越好？ |

## 二、评分机制一：综合得分（Critic 智能评审）

### 2.1 维度构成

Critic Agent 从 **五个维度** 对科学假设进行评审（[agent_critic.py 中的 DimensionScores 模型]）：

| 维度 | 含义 | 权重 |
|---|---|---|
| **evidence** | 证据支撑度——假设是否有文献/证据支持 | 0.25 |
| **falsifiability** | 可证伪性——假设是否明确给出可被推翻的条件 | 0.25 |
| **consistency** | 内部一致性——假设内部逻辑是否自洽 | 0.20 |
| **novelty** | 新颖度——假设是否具创新价值 | 0.15 |
| **cross_domain** | 跨学科性——假设是否融合多学科视角 | 0.15 |

### 2.2 加权计算公式

```
overall_score = evidence×0.25 + falsifiability×0.25
              + consistency×0.20 + novelty×0.15
              + cross_domain×0.15
```

- 各维度由 LLM 在 0–10 打分
- 权重体现优先级：**证据支撑与可证伪性是科学假设的第一要务**（合计占 50%），其次是一致性，最后才是新颖度与跨学科

### 2.3 核心优势

1. **多维度、可解释**：单一分数被拆解为 5 个可追溯的子分数，用户在界面上可看到"哪个维度拖了后腿"。
2. **科学导向的权重设计**：将 evidence/falsifiability 权重顶到 0.25，避免"花哨但没依据"的假设得高分——这符合科学方法论优先原则。
3. **LLM 语义评审**：不是机械关键词匹配，而是理解假设的完整语境后打分，能够识别 deep 但表面字数相近的假设差异。
4. **温度可调**：Critic 的 temperature 从 0.5 降到 0.3，在"打分可复现"与"评审有一定多样性"之间取得平衡，降低随机波动。

## 三、评分机制二：颗粒度得分（算法客观计算）

### 3.1 三级计划模型

每条假设的 `plan` 字段包含三级递进的细节层次：

| 级别 | 含义 | 权重 | 示例 |
|---|---|---|---|
| **L1** 概念级 | 方向性描述，无具体数字 | 1 | "通过 do-calculus 进行因果效应识别" |
| **L2** 量化指标级 | 含具体数值/百分比阈值 | 3 | "后门准则满足度 ≥ 95%，混淆偏差 ≤ 5%" |
| **L3** 容错级 | 含备选方案与对照设计 | 6 | "若后门准则无法验证，改用前门准则；设置随机化对照" |

### 3.2 加权计算公式

```
颗粒度得分 = (Σ L1×1 + Σ L2×3 + Σ L3×6) / 假设总数
```

加权逻辑体现 **"具体可操作 > 理论可行 > 泛泛而谈"**：
- L1 只给 1 分——有概念方向是底线
- L2 给 3 分——有量化指标才有可验证性
- L3 给 6 分——有容错/备选方案才称得上稳健的科学设计

### 3.3 分数区间解读

| 分数 | 含义 |
|---|---|
| 1.00 | 所有假设仅停留在概念层（纯方向） |
| 2.00 | 平均达到 L1+L2 水平（有量化指标） |
| 3.33 | L1/L2/L3 三级齐全（当前默认值，见下） |
| 6.00 | 满分，所有假设都有完整三级深层设计 |

### 3.4 核心优势

1. **客观、零成本、可复现**：纯粹由算法按公式计算，不依赖 LLM，同一份假设永远得到同一分数。
2. **公式化、可解释**：分数可直接拆解回"几条带数字的 L2、几条带备选方案的 L3"，方便用户理解为什么是这个分数。
3. **与 LLM 综合评分互补**：综合得分衡量"质量质量"，颗粒度衡量"细节丰富度"，两条线互不干扰，共同给出更立体的评估。

### 3.5 已知边界与优化方向

- **当前瓶颈**：Scientist 的 System Prompt 强制"每条假设都必须包含 L1/L2/L3"，导致统计恒为 3/3/3、得分恒为 3.33，指标暂时失去区分度。
- **优化方向**：将颗粒度统计从"检查有无"升级为"评估内容丰富度"——例如 L2 要求"含数字 + 足够长度"，L3 要求"含备选/对照关键词 + 足够长度"，使敷衍的二级计划无法拿满分，真正拉开分数差距。

## 四、评分机制三：跨轮次迭代评分闭环

### 4.1 迭代链路（V1 → V2 → V3）

```
V1 跑完 → 写入 snapshots/V1.json（含 Critic 全部评审 + overall_score）
        ↓
V2 开始时 → Orchestrator 读取 V1.json，提取 critic_output + overall_score
        ↓
     注入 Scientist Prompt ← 结合上一轮 Critic 评审意见
       ↓
V2 跑完 → Critic 得到 prev_scores(V1) → 对比验证改进是否到位
        ↓
       输出 📈提升 / ⚠️退化 对比日志
        ↓
V3 同理，V3 为最大迭代上限（边界保护）
```

### 4.2 两大核心设计

**① Critic → Scientist 的改进传导**
Orchestrator 在 V2/V3 开始时读取上一轮快照，把 Critic 的 **五维评分、top_flaw（致命缺陷）、missing_evidences（缺失证据）** 注入下一轮 Scientist 的 Prompt，并在 Prompt 中给出"目标至少提升 0.5 分"的明确要求。

**② Critic 的跨轮次纵向评审**
Critic 在评审当前轮时收到 `round_label` 和 `prev_scores`，会**对比上一轮分数**，验证"新增改动的假设是否真的比上一轮好"，同时在 Prompt 中注入"不得放水"的硬约束。

### 4.3 核心优势

1. **从"重跑"变成"修正"**：之前的迭代是每轮独立生成假设（Scientist 不知道上一轮哪里被骂），现在是"上一轮的错误显式传给下一轮"，真正实现有记忆的迭代优化。
2. **可观测的迭代效果**：每轮结束打印对比日志，运营同学能直观看到评分是提升还是退化（如 `📈 V2 评分较上一轮提升 0.85 分`）。
3. **闭环验证**：Critic 不只是"再打一次分"，而是"确认这次改进是否真的到位"，避免假设越改越偏。

## 五、评分机制的联动关系图

```
                      ┌──────────────────────────────────────┐
                      │          Agent 流水线执行一轮         │
                      │  Explorer → Scientist → Critic       │
                      └──────────────────┬───────────────────┘
                                         ↓
                    ┌────────────────────┼────────────────────┐
                    ↓                    ↓                    ↓
           综合得分 (Critic)       颗粒度得分 (算法)      快照持久化
           五维权重加权           L1/L2/L3 加权          JSON文件 + DB表
                0–10                 1–6
                    └────────────────────┼────────────────────┘
                                         ↓
                          ┌──────────────────────────────┐
                          │  下一轮迭代开始（V→V+1）       │
                          │  读取上一轮快照 → 注入         │
                          │  Scientist AND Critic         │
                          └──────────────────────────────┘
                                         ↓
                             评分对比 → 提升/退化日志
```

## 六、结论与最佳实践沉淀

1. **评分必须多维**：单一的 LLM 分数可解释性差，拆成独立且权重明确的维度（evidence/falsifiability 优先）让系统更可信。
2. **客观指标 + 主观评审并用**：LLM 综合分保证深度，算法颗粒度分保证公平，两者互补。
3. **迭代 = 修正，而不是重跑**：跨轮次传递上一轮评审，是让"迭代真的在变好"的关键基础设施。
4. **指标要有区分度**：颗粒度恒为满分说明"必填约束 + 有无判定"的组合会破坏指标价值，需要把硬约束改成梯度评分。
5. **天然防止退化（改进建议）**：当前 V3 已实现上一轮注入与对比日志；如需更强保障，可为综合得分加"单调约束"（若低于上一轮 ×0.95 则自动重评一次，取两次最大分）。
